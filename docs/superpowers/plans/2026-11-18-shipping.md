## 원본 숫자 규칙 (Task 2 가 구현, 모든 화면이 따름)

- `int.Parse(x.ToString())`: null·빈 값·정수 아님 → ParseError. `float.Parse`: null·빈 값·숫자 아님 → ParseError, 값은 `Math.fround`. `decimal.Parse(double.ToString())`: null·빈 값 → ParseError, 0 이 아닌 `|v| < 1e-4` 또는 `|v| ≥ 1e15`(원본 ToString 이 지수 표기 → decimal.Parse 실패) → ParseError, 그 외 유효숫자 15자리 반올림.
- 목록 변환 중 ParseError 가 나면 **그 행부터 버리고 앞 행만 쓴다**(원본은 foreach 밖 catch).
- C# `float` 연산은 매 연산 `Math.fround`. `(decimal)(float식)` = 유효숫자 7자리 반올림, `(decimal)(double식)` = 15자리 반올림.
- 원본 `float.ToString()` 으로 SP 문자열에 넣던 값은 `floatArg`(생산 LOT 팝업에 있음)로 만든다.

## Rulings (계획 단계)

- **K (새로 발견)**: LOT 화면 행 체크박스는 원본에서 표 선택 행에 변경됨·합계를 적용하고, 선택이 없으면 앱이 죽는다 → **누른 행에 적용 + 그 행 선택**. B와 같은 기준(1+3), 생산 재고 팝업 버그 29 선례. 사용자에게 보고한다.
- **저장 중 통신 오류**: 원본 `SetData` 는 DB 오류를 삼키고 0 을 돌려 다음 행을 계속한다. 웹도 실패한 행은 0건으로 세고 다음 행을 계속 보낸다. 실패가 하나라도 있으면 끝난 뒤 `"서버와 통신할 수 없습니다."`(로그인 만료면 기존 공통 처리)를 **한 번** 띄우고, 그다음 원본 규칙(성공 1건 이상이면 성공 알림 → 닫기)을 따른다.
- **원본 parse 도우미 이동**: `prodLot.ts` 의 `ParseError`·`parseInt32`·`parseFloat32`·`floatArg` 를 `frontend/src/shared/dotnet/dotnetNumber.ts` 로 옮겨 두 화면이 같이 쓴다(동작 변화 없음, 기존 prodLot 테스트로 확인).
- **leftover 파일**: `backend/src/test/java/com/mokyang/pop/shipping/ShippingControllerTest.java` 는 되돌린 작업이 git 제외 폴더에 남은 것(지금 `mvn test` 컴파일을 깨뜨림). Task 1 이 새 내용으로 **덮어쓴다**.

## Review Focus

1. **행을 먼저 누르지 않고 [선택]·체크박스·출고량 칸을 누름**(선택 해제 상태 포함) — 누른 행에 적용되고 죽지 않는다(Task 3·4 테스트).
2. **Roll/Box 에 1,500 입력 / 소수 값에서 취소** — 꺼지지 않고, 입력은 다시 계산, 취소는 원본 규칙대로(정수이고 1,000 미만일 때만 다시 계산)(Task 2 테스트).
3. **저장 중 한 행이 서버 오류** — 남은 행을 계속 보내고, 통신 오류 알림 한 번 뒤 성공 1건 이상이면 성공 알림·닫기(Task 4 테스트).
4. **LOT 화면을 다녀온 뒤** — 출하 목록의 날짜·품목명·수주구분·진행구분이 그대로이고 목록을 다시 조회한다(Task 4 테스트).
5. **바코드 9자·11자 / 없는 LOT 10자** — 9·11자는 반응 없음, 없는 LOT 는 알림 후 칸 비움·선택 해제, 그 뒤 체크박스를 눌러도 죽지 않음(Task 4 테스트).
