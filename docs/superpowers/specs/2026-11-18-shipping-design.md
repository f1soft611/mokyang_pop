## 6. 구조

### 6-1. 백엔드 (`backend/.../pop/shipping`)

API **[내 판단]** — 경로·이름은 구현자가 바꿔도 됨. 응답은 기존처럼 컬럼명(대문자) 그대로(`SpRows.normalize`).

| 용도 | API | 호출 |
|---|---|---|
| 출하 목록 | `GET /api/shipping/list?date=yyyyMMdd&materialName=&status=` | `SP_CPOP301_01_LIST2(로그인 공장코드, date, materialName, status)` |
| 수주구분 목록 | `GET /api/shipping/order-gbn` | 원본 ComboModule `Get_OrderGbn("520")` SELECT 그대로, `CODE_ID2 AS CODE, CODE_NAME_FULL AS NAME` |
| LOT 목록 | `GET /api/shipping/lot/list?factoryCode=&materialCode=&shipplanSeq=&lotNo=&qty=` | `SP_CPOP301_WIN02_01_LIST` |
| LOT 저장(한 행) | `POST /api/shipping/lot/iud` | `SP_CPOP301_WIN02_01_IUD`, 결과 = 영향 행 수(원본 `SetData` 반환값) |

- **공장코드**: 목록 SP는 로그인 정보의 공장코드(원본 `Settings.factory_code`). LOT 목록은 목록 행의 FACTORY_CODE(원본 `pModel.FactoryCode`). 저장은 LOT 행의 FACTORY_CODE(원본 `row.FactoryCode`). 생산실적과 같은 규칙.
- **@OPMAN_CODE**: 로그인 사번(서버 세션). 원본은 비면 `"0000"` — 웹은 로그인 뒤에만 들어오므로 항상 사번이 있다.
- **@SHIPPLAN_SEQ**: LOT 행 값, 비면 출하 행 값 — 화면이 정해서 보낸다(원본 그대로).
- **인자 형식**: 원본이 VarChar 로 넘기던 것(`@LOT_SEQ` 포함)은 문자열로 바인딩, `@OUTPUT_QTY`·`@OUT_QTY_ROLL_BOX`·`@REST_QTY` 는 숫자. 값은 원본과 같게.
- **저장 결과 건수**: 원본은 `ExecuteNonQuery()` 반환값이 `== 1` 인 행만 성공으로 센다. 이 값은 SP 안 INSERT/UPDATE/DELETE 영향 행 수의 **합**이다. 2026-11-18 확인(조회만): SP에 `SET NOCOUNT ON` 없음, `TSA407L` 에 트리거 없음. `IU` 는 UPDATE(0 또는 1) 후 0이면 INSERT(1) → 보통 1, `D` 는 DELETE 행 수(저장 안 된 LOT 이면 0). **서버는 모든 영향 행 수를 더해 돌려준다** — JDBC 첫 번째 update count 만 읽으면 `IU` 의 INSERT 경우 0 이 되어 틀린다. MyBatis 기본 `<update>` 반환값에 기대지 말고, 모든 결과를 돌며 합산하는 방식으로 구현하고 컨트롤러/매퍼 테스트로 확인한다.
- **저장은 행마다 한 번씩**: 화면이 변경된 행을 순서대로 하나씩 호출한다(원본처럼 묶음 없음). 한 행이 실패해도 다음 행을 계속 보낸다(원본은 예외를 삼키고 계속).
- 시험: `-Pdev-db` 통합 테스트로 조회 SP 2개와 수주구분 조회를 실제 호출해 컬럼을 확인한다. **저장 SP는 자동 테스트에서 부르지 않는다.** 컨트롤러는 DB 없이 매퍼를 가짜로 바꿔 시험한다.

### 6-2. 화면 (`frontend/src/pages/shipping`)

- **화면 전환** **[내 판단]**: `App.tsx` 의 화면 상태에 `shipping` 을 추가하고, 메인메뉴 `MainMenuPage` 에 `onOpenShipping` 을 연결한다(지금은 반응 없음 — 출하만 켠다). LOT 선택은 출하 화면 위에 덮는 화면으로 띄우되, **출하 목록 화면의 검색 조건은 그대로 남아야 한다**(원본은 뒤로가기로 같은 페이지로 돌아옴). LOT 화면을 닫으면(저장 성공 포함) 출하 목록을 다시 조회한다.
- **레이아웃**: 1920 기준 픽셀(원본 `*` 비율을 1920x1080 에서 계산한 값)과 인벤토리의 색·글자 크기를 따른다. 기존 `ScaledStage` 안에서 그린다.
- **재사용**

- **목록 ▲▼**: 목록 오른쪽 5% 폭의 세로 줄을 위·아래 반씩 나눈 큰 버튼(원본 `Grid.Row` 0/1 각 `*`).
- **행 선택 표시**: 선택 행 주황 `#C96B00` + 위아래 흰 테두리 2. 조회 직후 첫 행 자동 선택(원본 `IsSynchronizedWithCurrentItem`). LOT 화면도 같은 선택 표시.
- **계산 로직**: `Calc_RollBoxQty`, `Calc_ItemQty`, 체크/전체체크의 총 출고량·변경됨 처리, `AutoSetting`, `SaveValidation`, STOCK_ROLL_BOX 1 미만 올림, 초기 체크·총 출고량 계산을 **화면과 분리된 순수 함수**로 만들고 원본 분기마다 단위 테스트한다. 숫자 형식은 원본 타입을 따른다(생산실적 LOT 팝업 `prodLot.ts` 선례): 원본 `float` 칸(OutPutQty, StockQty, SlitterBox, Item* , MaxRollBoxQty, SaveValidation 합계)은 `Math.fround` 로 32비트 값으로 맞추고, 원본 `decimal` 칸(OutQtyRollBox, StockQtyRollBox, TotalSelectedQty)은 그대로 number. 저장 때 `@OUTPUT_QTY` 에는 32비트로 맞춘 값을 그대로(double로) 보낸다(원본 `SqlDbType.Float` 에 float 를 넣은 것과 같음). [적용] 수량 비교도 원본처럼 32비트 합계 vs 출고지시량.
- **숫자 칸이 비어 오는 행** **[내 판단]**: 원본은 숫자 칸을 `float.Parse`/`decimal.Parse` 로 읽다가 비어 있으면 예외 → 그 행 **앞까지만** 목록이 채워진다(LOT 화면은 Total Rows 가 이미 전체 건수로 들어간 뒤). 원본 로직과 달라지는 수정 금지 원칙에 따라 **원본 그대로** 재현한다(생산실적 LOT 팝업 `applyLotFields` 와 같은 방식). SP 본문상 LOT 목록의 ITEM_ARRAY_ROLL 등과 출하 목록의 ROLL_BOX_QTY 는 NULL 이 올 수 있다.
- **로딩 표시** **[내 판단]**: 생산실적처럼 조회 중에는 "결과 없음" 문구 대신 진행 표시.
- **LOT 번호 칸**: 키보드 웨지 바코드 그대로 입력받고, 글자가 정확히 10자가 되면 원본 `AutoSetting`. 칸은 비운다.

2. 화면: 출하 목록(헤더·검색·목록·▲▼·[선택]) + 메인메뉴 연결
3. 화면: LOT 선택(조회·체크·숫자판·바코드·[적용]·닫기 후 목록 재조회) + 계산 순수 함수 테스트
4. 개발 DB 확인: 출고일 2024-06-21 목록 → [선택] → LOT 목록. [적용]은 사용자 확인 후 시험 데이터로 한 번(쓰기가 일어나므로 먼저 묻는다)

## 8. 시험 방법

- 계산: 순수 함수 단위 테스트(롤 004 / 봉투 가로 1 / 세로 2·3 / 그 외, 0 나눗셈 보호, 취소 규칙).
- 화면: Vitest + Testing Library. 수주구분·진행구분이 **선택창**으로 열리는지, 품목명 칸에 버튼이 없는지, 진행구분 처음 "전체", 진행상태 2 행의 [선택] 숨김(자리 유지), ▲▼ 이동, 누른 행으로 LOT 화면이 열리는지.
- 실제 화면 확인은 브라우저 DOM·텍스트로(캡쳐 금지).
- 저장 SP 는 자동 테스트에서 부르지 않는다.

## 9. 구현자에게 맡기는 것

- API 경로·DTO 이름, 파일 나누는 방식
- LOT 화면을 덮는 방식(같은 화면 안 겹치기, 화면 상태 추가 등) — 6-2의 "검색 조건 유지 + 닫으면 재조회"만 지키면 됨
- 순수 함수 묶는 방식, 테스트 도구 세부
