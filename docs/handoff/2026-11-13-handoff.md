이전 Claude Code 세션(원본 WPF 폴더에서 진행)의 내용을 이 프로젝트에서 이어가기 위한 문서.

## 1. 원본 프로그램 개요 (iPlusPOP)

- 위치: `C:\Users\USER\Downloads\1.POP\1.POP\iPlusPOP`
- WPF 데스크톱 앱(C#, .NET Framework 4.7.2). 생산 현장용 터치 키오스크(1920x1080, 전체화면, 중복 실행 방지).
- 구조: XAML 화면 + 코드비하인드 + `Module`(ViewModel 역할, `Notifier`로 바인딩) + `Model`(DTO).
- 데이터 접근: `Common/DBManager.cs`가 **SQL Server에 직접 접속**(API 서버 없음). SP를 `string.Format("EXEC SP_... '{0}'")` 문자열로 호출 → SQL 인젝션 취약.
- 화면 전환: `NavigationWindow` + Page. 흐름: 로그인 → 메인메뉴 → 업무 화면.
- 기기별 설정: `Properties.Settings`(Windows 사용자 설정)에 공정/작업장/설비/작업자 저장.
- 그 외 PC 기능: FTP 자동 업데이트(`F1soft.Framework.Update`), 로그 파일, Windows 화상 키보드(TabTip), 키보드 웨지 바코드 스캐너, DevExpress 기반 라벨 인쇄(`F1soft.Framework.Report` DLL).
- 보안 문제: `App.config`에 DB 계정/비밀번호 평문, `LoginModule.cs`에 `0000` 계정 마스터 비밀번호 하드코딩. (값은 문서에 옮기지 않음)

### 버그 처리 기준 (사용자 승인)

1. 의도는 코드에 보이는데 구현이 잘못된 것 → **의도대로 구현**
2. 업무 규칙/계산 방식 → **그대로 옮김**
3. 앱이 죽거나 데이터가 깨지는 오류 → **최소한으로 수정**
4. 애매한 건 설계 문서에 표시해서 검토받음

사용자가 개별 확인한 항목:
- 투입수량을 줄이면 자재 재고 상한도 같이 줄어드는 동작 → **그대로**
- 작업의뢰서 URL `_test` 하드코딩 → **그대로**
- 작업 중 공정 X 버튼이 보이는 문제 → 원래 의도(작업 중 못 지움)대로 구현.
  - 원인: `Production.xaml` 147/177/236/266/295줄 DataTrigger가 `{Binding ProdStatus}`인데 실제 값은 `ProdData.ProdStatus`라 트리거가 한 번도 동작하지 않음. `ClickClearField`(Production.xaml.cs:117)에도 상태 체크 없음.
  - 새 앱: `ProdStatus == "1"`(준비/본가동)일 때 공정·작업장 X/돋보기 숨김, 조회 버튼 비활성. `"2"`(작업중단)는 원본 조건대로 막지 않음.

## 3. 아직 정하지 않은 것 (다음 대화에서)

- [ ] **Electron 포함 여부**: "지금처럼 사용"하려면 설치형(전체화면, 중복 실행 방지, 자동 업데이트)이 필요 → Electron으로 감싸는 것을 기본안으로 제안해 둠. 사용자 미확정.
- [ ] **MD3 라이브러리**: React용 정식 MD3 라이브러리가 없음. 제안: MUI + MD3 테마(색상/모양/글꼴 토큰). 대안 `@material/web`은 유지보수 모드라 비추천. 현재 시제품은 MUI 사용.
- [ ] **백엔드 구조/배포 위치**: Spring Boot API 서버를 어디서 띄울지, Java 버전(Spring Boot 3.x는 Java 17+).
- [ ] **로그인**: 생산 화면이 로그인 정보(`factory_code`, 사번 `employee_cache` → 모든 IUD SP의 `@OPMAN_CODE`)를 쓰므로 DB 연결 시 로그인 화면(`SP_POP_LOGIN`)도 필요.
- [ ] **기기별 설정 저장 위치**: 공정/작업장/설비/작업자(`device_*`)를 PC 단위로 보관. Electron이면 로컬 파일, 브라우저면 localStorage.
- [ ] 화상 키보드(TabTip), 바코드(10자 자동 조회) 처리 방식.
